# Camelot 配布ページの設計

- 方向性: Claude Opus 5.5へのコマンドライン相談で得た案「静かな紙面に、ヒントだけが色を持つ」を採用。Claude CLIの利用結果は親タスクで確認済み。ここにはプロンプトや認証情報を保存しない。
- 参考: `../QuickDraw/docs/site/`の静的な配布ページ構成。LP、サポート、プライバシーを分け、依存のないHTML/CSS/JSにする。
- 見た目: 明るい紙色を基本にOSのダークモードへ追従。macOS標準の書体、細い罫線、黄色のヒントだけをアクセントにする。アプリのアイコンは`AppResources`の既存PNGをコピー。
- 表現: 日本語のみ。CamelotはmacOS 26以降、英語UI。サイト上のウィンドウは説明用の架空デモであり、実アプリのスクリーンショットではないと明記する。
- 操作: Option短押しの説明、文字ヒント、Esc/Backspace、ボタン実行と入力欄フォーカスをデモにする。実Option単独タップとキー入力、タッチ用ボタンに対応し、デモにフォーカスがあるときだけキーを扱う。自動再生なし、動きを控えるOS設定にも対応。
- 事実確認: アクセシビリティと入力監視が必要。macOSのAX情報を調べ、AXアクションが使えない場合は座標クリックへフォールバックする。実行時の診断表示に役割・タイトル・説明などを読み、アプリ内メモリ上で扱う。入力履歴、UI診断情報を永続保存せず、アプリはネットワーク通信しない。したがって「ラベルを読まない」「合成クリックをしない」とは表現しない。
- 配布状態: 公開Releaseはまだなく、公開リポジトリURLも確定していない。CTAは無効の「配布準備中」とし、ダウンロード先を推測しない。リリース時は`assets/site.js`冒頭の`RELEASE`を実在する検証済みURLとともに更新する。署名済みUniversal DMGを準備中と案内し、公証完了とは書かない。
- サポート: 自己解決手順を載せ、未確認のGitHub、メール、問い合わせ先を作らない。公開配布開始時に連絡先とインストール・削除手順を追記する。
- プライバシー: アプリのローカル処理とウェブサイトのホストログを区別する。解析タグは加えず、GitHub Pages使用時にホスト側ログがあり得る点を条件付きで説明する。公開方法が決まってからGitHubの現行プライバシー資料へのリンクを加える。
